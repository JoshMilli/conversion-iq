OVERVIEW
--------
We are running paid ads for Conversion IQ. The goal is a zero-friction lead
generation funnel: a user sees the ad, lands on a page, enters their email,
completes a short business profile form, and receives a free Professional-plan
license key — all in one flow. They then install the WordPress plugin, activate
their key, and the business profile syncs in automatically so their first audit
produces personalised, meaningful results immediately.

This is a lead generator for Webtec. Every user who activates becomes a warm
lead with full context about their business already in the system.

CRITICAL: The business profile is not optional. Without it, the plugin's AI
audits produce generic results and the plugin will block audit runs entirely
(it requires industry, product, audience, and goal to be filled). The onboarding
form must be completed before the license key is revealed.

No changes are needed to the WordPress plugin. All work is on the
conversioniq-app.com backend and a new landing page.


================================================================================
PART 1 — HOW LICENSE ACTIVATION WORKS (plugin side, read-only context)
================================================================================

When a user enters a key into the plugin, it POSTs to:

  POST https://conversioniq-app.com/api/validate-license
  Content-Type: application/json

  {
    "license_key": "CIQ-XXXXX-XXXXX-XXXXX-XXXXX",
    "site_url": "https://their-wordpress-site.com",
    "organization_id": "optional-existing-org-id"
  }

The plugin expects this exact response shape on success (HTTP 200):

  {
    "valid": true,
    "api_key": "sk-...",
    "organization_id": "uuid",
    "customer": {
      "name": "string",
      "email": "string",
      "company": "string",
      "plan": "professional"
    },
    "message": "License activated successfully!"
  }

On failure: HTTP 400 with { "valid": false, "message": "reason" }

The key format is validated by the plugin with this regex:
  /^CIQ-[A-Z0-9]{5}-[A-Z0-9]{5}-[A-Z0-9]{5}-[A-Z0-9]{5}$/i

After successful activation the plugin also calls:
  GET  https://conversioniq-app.com/api/get-business-profile
  POST https://conversioniq-app.com/api/deactivate-license  (on deactivation)
  POST https://conversioniq-app.com/api/license-sites       (to list active sites)

These endpoints already exist and should continue to work for promo keys
exactly as they do for paid keys.

PART 3 — CLAIM PROMO KEY ENDPOINT
================================================================================

NOTE: The key claim endpoint now receives business profile data alongside the
email. The onboarding form (Part 8) is submitted first; this endpoint is called
with both the email and the completed profile in a single request.

Build a new endpoint:

  POST /api/claim-promo-key
  Body:
  {
    "email": "user@example.com",
    "utm_source": "google",
    "utm_campaign": "ad-campaign-2026",
    "profile": {
      "business_name": "string",
      "industry": "string",
      "product": "string",
      "audience": "string",
      "goal": "string",
      "pain_points": "string"
    }
  }

  Success response (HTTP 200):
  { "success": true, "license_key": "CIQ-XXXXX-XXXXX-XXXXX-XXXXX", "already_claimed": false }

  If email already claimed a key, return the same key and update the profile:
  { "success": true, "license_key": "CIQ-XXXXX-XXXXX-XXXXX-XXXXX", "already_claimed": true }

  Error (HTTP 400):
  { "success": false, "message": "reason" }

Logic:
- Validate the email
- Validate that profile.industry, profile.product, profile.audience, and
  profile.goal are all present and non-empty (these four are required by the
  plugin to run audits — reject the request if any are missing)
- Check if this email already has a promo key assigned — if so, update their
  profile with any new data and return the existing key
- Otherwise:
  1. Create an organization record in Supabase linked to this email
  2. Save the full business profile to that organization
  3. Assign the next available unused promo key to this email and org
  4. Record: email, license_key, organization_id, claimed_at, utm_source,
     utm_campaign in the promo_leads table
  5. Send a confirmation email to the user (spec in Part 4)
  6. Return the key

IMPORTANT — Profile sync on plugin activation:
The existing /api/get-business-profile endpoint is called by the plugin
immediately after license activation. It must return the profile saved here
when looked up by license_key + site_url. This is how the business profile
flows into the plugin automatically with zero effort from the user.

created at claim time via /api/claim-promo-key. When the plugin later calls
/api/get-business-profile (on license activation), it must be able to retrieve
this profile by matching on license_key + site_url. Ensure the organization_id
from the promo claim is stored on the license key record so the existing
business profile lookup path works correctly.

PART 6 — LANDING PAGE
================================================================================

Build a standalone landing page at /free (or /free-audit — your choice).

DIRECTION FOR COPY
The tone should be direct, confident, and benefit-led — not hype-y. The reader
is a WordPress site owner or marketer who is losing conversions and doesn't know
why. They're skeptical of yet another tool. The copy should quickly establish
that this is an AI that reads their actual page and tells them specifically what
to fix, not generic advice. Emphasise that it's genuinely free (no card, no
catch), the setup takes 2 minutes, and the output is a prioritised action list
they can act on today. Use short sentences. Make the value concrete — scores,
specific suggestions, copy rewrites. The CTA is "Get Free Access."

PAGE STRUCTURE (sections in order):

1. HERO

   - Primary CTA button: "Get Free Access" — scrolls to the key claim section

   Step 1: Install the free plugin
   Step 2: Enter your free Professional key (generated on this page)
   Step 3: Run your first AI audit

3. WHAT YOU GET — feature grid (6 items)
   - AI audit with 6 conversion scores
   - AI copy suggestions & rewrites

   - Priority support

5. KEY CLAIM SECTION (the lead capture — 3-step flow in one section)

================================================================================
PART 8 — ONBOARDING FLOW SUMMARY
================================================================================

The complete user journey on the landing page is:

  [Ad click]
      ↓
  [Landing page]
      ↓
  [Step A] Enter email
      ↓
  [Step B] Fill in business profile (6 fields, all required)
      ↓
  POST /api/claim-promo-key  ← email + profile + UTM params sent together
      ↓
  [Step C] Key is revealed on-page + emailed
      ↓
  [User installs plugin + enters key]
      ↓
  Plugin calls /api/validate-license → key is valid, org_id returned
      ↓
  Plugin calls /api/get-business-profile → profile syncs into plugin automatically
      ↓
  User runs their first personalised AI audit immediately

This flow ensures:
- We capture the lead (email) early
- The AI has everything it needs before the user even opens the plugin
- The user's first audit result is specific and impressive, not generic
- Webtec has full business context on every lead in the CRM from day one

FAILURE STATE TO HANDLE:
If the user skips the profile form or submits incomplete data, do not reveal
the key. Show inline validation on Step B fields with clear messages. The key
must not be issued until all four required fields (industry, product, audience,
goal) are present.
